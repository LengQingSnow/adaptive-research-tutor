# 上下文、版本与检查点

## 读取顺序与能力降级

先确认当前知识点与实际可访问的范围，再读最小相关材料：用户指定文件/片段 → 学习位置 → 最近相关检查点 → 必要源码、文档、实验输出。目录不明时用有针对性的文件搜索，不逐轮全项目扫描。

| 实际能力 | 做法 |
| --- | --- |
| 可使用关联 Side Chat 或用户已指定的独立教学聊天 | 利用已有会话；只通过实际可用且获准的读取能力访问主任务。关联不代表实时共享上下文。 |
| 能读共享项目，但不能读主聊天 | 通过可见文件和检查点教学，明确截至哪个版本/里程碑。 |
| 只有用户给的片段 | 基于片段解释，将整体实现判断标为未确认；可请求最小必要上下文。 |
| 没有任务资料 | 说明无法确认任务内容；问任务目标或请提供一个相关片段，仍可先解释用户指定的通用概念。不声称已同步或已构建项目知识图谱。 |
| 不能写学习资料 | 会话内维护位置，按需给可复制的恢复摘要；不得声称已保存到磁盘。 |

打开/创建聊天与跨聊天发消息使用各自的用户授权边界；启动课程本身不等于授权创建新聊天或向其他聊天发送消息。主任务和导师的两个独立聊天由平台调度，Skill 本身不是并行执行器。

## 同步一次可见进度

在用户请求同步、恢复时发现版本不同，或讲解必须确认实现时：

1. 读取最近相关检查点和当前点相关文件；可用时读取 Git 提交标识和相关工作区差异。没有 Git 时用文件指纹、文件版本或明确标注的观察时间；时间戳本身不证明内容相同。
2. 分别记录 `main_observed`（本次真正看到的主任务版本）和 `lesson_basis`（当前解释依据）。提交 SHA 不覆盖未提交修改：有相关修改时同时标注 dirty 状态或相关文件指纹。
3. 检查当前点的定义/机制/实现对应是否变化。保留旧版本锚点及历史说明；旧实现不再适用于当前版本时明确指出，不把它继续描述为最新实现。原文不可访问时说明无法重现旧代码。
4. 把新增的重要概念加入队列，关联变更证据和依赖。保留当前 active、卡点及原讲解版本。通用概念的已理解状态不因无关修改而重置；确需重新核对的实现点标为 `revisit` 并保留历史确认。
5. 用简短增量说明变了什么、尚未验证什么。只说“已同步到本次可访问的检查点/文件版本”，不承诺之后自动同步，也不等待主任务停下来。

检查点与当前源码冲突时分开陈述，指出先后或证据缺口。旧测试只能证明它覆盖的版本和条件；没有新结果不能沿用为新实现验证通过。若文件正在变化，本次讲解按注明的快照/观察范围进行，必要时再读取当前点相关文件；不为追求一致视图要求开发暂停。

## 里程碑检查点

只有主开发会话明确启用该集成、且目标学习文件可写时，才让主开发会话在有意义的里程碑追加检查点。检查点记录事实，导师按需读取；没有后台监听、跨会话推送或逐文件自动生成要求。

主任务是 `checkpoints.md` 的写入者；导师是其学习会话进度文件的写入者。导师看到的新变化可记进自己的进度，不能冒充主任务检查点。多人或多会话时给各自明确的文件所有者。

每个条目采用稳定 ID，并包含：

```yaml
id: cp-0002
task: sensor-gateway
observed_at: "2026-10-23T10:00:00+08:00"
version:
  kind: snapshot
  ref: gateway-v2
  dirty: unknown
completed: ["用最近三条读数的滑动窗口替代分批均值"]
changed_files: ["src/gateway.py::window_mean"]
decisions: ["每次读数更新输出，接受窗口重叠"]
knowledge_candidates: ["滑动窗口与分批窗口的区别"]
validation:
  - action: "边界测试"
    result: not-run
open_issues: ["不足三条读数时的处理待确认"]
```

这是格式示例，不能当作真实项目检查点。`kind` 可用 commit、snapshot、file-hash 或其他已有标识；不能获得版本时设为 unknown，保留实际观察时间和范围。不要编造提交号。

## 可选 AGENTS.md 集成片段

仅当用户明确选择启用时，按项目已有规则合并以下片段。创建本 Skill 不应用此片段、不修改 `AGENTS.md`。其中 `docs/learning/` 是没有项目约定时的备选位置。

```markdown
### 可选学习检查点（主开发会话）
已启用本项目的学习检查点。在功能完成、关键设计变更或实验结论等重要里程碑后，由主开发会话向 docs/learning/checkpoints.md 追加一个简短条目：唯一 ID、任务、观察时间、可用版本标识及相关未提交修改、完成内容、改动文件/模块、核心设计决策、新增知识候选、实际验证及结果、未解决问题。版本未知则注明，不沿用旧测试为新版本背书。
保持主任务继续执行，不等待导师或用户学习。只记录必要增量，不复制大量源码或敏感数据，不逐次微小修改生成记录。此文件由主开发会话写；导师只读检查点，独立维护获准的学习进度文件。若写入不可用，报告一次并继续主任务，不擅自更改权限。
```

没有这一集成时，导师仍可从可读工程文件或用户提供的资料教学，不要求用户配置它之后才能开始。
